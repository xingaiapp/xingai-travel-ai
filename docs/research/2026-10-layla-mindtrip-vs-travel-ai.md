# Travel AI 复评：对比 Layla、Mindtrip（2026-10）

**日期：** 2026-10-05（America/Chicago）
**我方：** Travel AI，https://travel.xingai.app，线上生产环境
**对手：** Layla（https://layla.ai）、Mindtrip（https://mindtrip.ai）
**场景（与 2026-09 SearchSpot 对比相同）：** SFO 出发，2026-12-10 至 12-15（5 晚），总预算 $2,000，2 人情侣，慢节奏，城市风格；想要温暖、适合步行、美食；避开长途飞行和酷热。
**方法：** 内置浏览器，手机宽度（375×812）。全程未注册、未登录，未填写个人信息或支付信息。Cookie 选「Reject all」。
**局限：**
- 我方核心流程今天在线上直接报错（见第 3 节），**没拿到我方推荐结果**。我方结果维度引用 2026-09-28 的实测，并注明。
- Mindtrip 点「Set up your travel assistant」后出现 bot 验证（Additional Verification），按规则没有处理，所以**没拿到它的结果**。Mindtrip 一栏除首页定位外都是「自述」。
- 只测了手机宽度，没有测桌面端。

## 0. 一句话结论

**最直接的竞品是 Layla，而且它已经做出了我们的核心形态。** 它的「Inspire me where to go」免注册，几秒内给出「首选 + 备选 + 为什么不选」。它在这次测试里也违反了两个硬约束，这正好是我们能守住的差异。但前提是我们自己的线上服务能正常出结果。今天我们出不了结果。

## 1. 定位（Step 0）

| | Layla | Mindtrip | Travel AI |
|---|---|---|---|
| 回答的问题 | 「去哪 + 怎么安排 + 帮你订」（实测：灵感入口给首选和备选，之后自动生成行程并给出结账） | 「懂你的私人旅行助理」：记住偏好、帮你订、提醒降价（首页自述） | 「去哪」：1 个首选 + 2 个备选 + 取舍 |
| 旅程阶段 | 灵感 → 决策 → 规划 → **站内预订** | 规划 → 预订 → 行中（自述） | 决策 → 给可预订方案（联盟链接） |
| 市场 | 默认 USD、英文；首页示例遍及全球 | 美国（首页示例 SFO-LAX） | 美国出发为主，USD；en/zh/ko/es |
| 是否直接竞品 | **是**，而且是最直接的 | 部分重叠。它在往「个人助理 + 记忆」走，决策只是其中一环 | — |

**需要修正的旧判断：** 2026-09 的 Layla 对比里写过「Layla 默认你已知道去哪」。这一点**不再成立**。Layla 首页第二个按钮就是「Inspire me where to go」，而且实测给出了首选、3 个备选和每个备选的淘汰理由。「先比目的地」已经不是我们独有的形态。

## 2. 逐项对比

标注：**实测** = 本次亲手测；**旧实测** = 2026-09-28 我方实测；**自述** = 对方官网说法。

| 维度 | Layla | Mindtrip | Travel AI | 谁更强 |
|---|---|---|---|---|
| 到第一个结果前的步骤 | 实测：首页 → 点「Inspire me」→ Cookie 横幅 → 聊天。无注册墙，到行程页和结账页也没要求登录 | 实测：点主按钮后出现 bot 验证，没进到产品 | 实测：表单已预填，一次点击。**但今天提交后报错** | 今天是 Layla。平时打平（都免注册） |
| 速度 | 实测：首轮推荐约数秒；确认后生成完整行程约 40 秒 | 未测到 | 旧实测约 5 秒。今天上午约 1.5–2.6 秒后报错，下午复测约 17.7 秒后报错 | 平时我们快 |
| 输入方式 | 对话。一句话就能把全部约束说完；会先复述行程摘要（路线、日期、人数、预算），确认后再生成 | 对话 + 偏好问卷（自述） | 结构化表单 + 风格/节奏 + 备注 | 各有长处 |
| 推荐和淘汰理由 | 实测：首选 Oaxaca；备选 Mexico City（12 月晚上偏冷、人多）、San Diego（不够暖、预算紧）、Cartagena（太湿热、航程长） | 自述：会解释为什么适合你 | 旧实测：首选 + 2 备选，每个一句「为什么不选」，另有对比表和 Match Score | 打平。形态已经基本一样 |
| **硬约束：避开长途飞行** | 实测：**违反**。首选 Oaxaca，生成的去程是 27 小时 4 分、2 次转机、次日才到。Layla 自己在航班卡片里写了「这个行程不适合 5 晚旅行」，但折叠在「Read more」里，首选没有因此改变 | 未测到 | 旧实测：普通比较模式**也没完全守住**（Lisbon 约 12 小时仍进了备选）；Surprise me 模式会在服务端校验航程 | 都没做到。谁先把它做成硬约束谁赢 |
| **硬约束：预算 $2,000** | 实测：**超出**。行程合计 $2,558，刷新后 $2,454。推荐语却写着预算在这里「很宽裕」 | 未测到 | 旧实测：直接判「偏紧」，并给出 5 类费用的估算区间 | **我们**（显式对照预算） |
| 内部一致性 | 实测：第 1 天行程排在 12-10 的 Oaxaca，但航班 12-11 中午才到 | 未测到 | 旧实测未发现 | 我们（单方面） |
| 价格数据 | 实测：像是实时报价。酒店价格两次查看从 $987 变成 $883，航班 $1,160/2 人 | 自述：降价提醒 | 估算区间，注明「不是实时报价」 | **Layla** |
| 用户怎么下单 | 实测：**站内自助结账**（勾选酒店、机票、接送、体验，合计一键付款）；也可以交给免费真人专家代订 | 自述：站内直接订，或让助理代办 | 联盟链接，预填日期和人数 | **Layla** |
| 提醒与风险 | 实测：有，但折叠起来，摘要里看不到 | 自述：天气、航班变动提醒 | 旧实测：4 条分级提醒 + 不确定性面板 | 我们（更显眼） |
| 分享和导出 | 实测：行程页有分享和下载图标 | 未测到 | 分享链接 + 打印/PDF | 打平 |
| 偏好记忆 | 有「Trip checklist」，单次对话内记忆 | 核心卖点：长期记忆偏好（自述） | 无账号，本机保存最近 12 次决策 | Mindtrip |
| 渠道 | 网页 | 网页 + iOS App（自述） | 手机网页 | 对手 |
| 收费 | 实测：AI 和专家都标「免费」，靠预订赚钱 | 未测到 | 免费，联盟佣金 | 打平 |

## 3. 我们自己的问题（本次实测）

### P0：线上核心流程不可用

- **复现：** 打开 https://travel.xingai.app/decide，填入上面的场景，点「Compare destinations →」。约 1.5–2.6 秒后页面显示「We couldn't complete the recommendation. Try again.」。重试结果一样。
- **接口：**
  - `POST /api/compare` 返回 502 `{"error":"Decision unavailable","code":"OPENAI_ERROR"}`。
  - `POST /api/inspire`（Surprise me）同样 502，但 code 是 **`INSPIRE_CONSTRAINTS`**，不是 `OPENAI_ERROR`。
  - 输入校验正常（空请求返回 400）。
- **失败文案时间线：** 2026-10-05 **09:19** 的提交（`e6a81bb`）起，API 失败响应已改成固定的 `Decision unavailable`（此前会把 OpenAI 报错原文带回响应）。下午 Redis / 埋点 / CI 那批**没有**再改 `openai.chat.completions.create` 的参数（模型、`max_tokens`、temperature）。
- **部署说明：** 今天下午与 Redis 限流、埋点、CI 相关的提交约 5 个（其中靠后的文档/Node 调整可视为同一轮上线），但下午**不止**这几次生产部署——还有首页轮播、SEO/footer 等多轮。不要把「下午 5 次」理解成当天全部 Production 部署数。
- **线索：** 失败很快（两次 OpenAI 调用加起来不到 2 秒），更像是认证、额度或模型名的问题，不像超时。
- **指标（Redis，`npm run metrics`）：** 埋点从今天下午（`7c3e130`）才写入 Upstash。因此**不能**用过去几天的 `decision_ok=0` 单独证明「过去 3 天都没有成功推荐」。**今天**的计数是：`decision_ok` 0；`decision_fail` 3（compare 2、inspire 1）；另有 rate-limit。同一出口 IP 的每日 3 次额度用完后，后续请求约 0.2 秒回 429，无法再复现当天的 502 时延。
- **根因未确认：** 复测当时 `app/api/compare/route.ts` 把 OpenAI 异常吞掉了，日志里看不到状态码。后续已加上安全日志（status / type / `finish_reason`，不记 key/prompt）；部署后需再复测一次才能对照 Vercel 日志。

#### 复测（同日，约 16:20–16:30 CDT，报告「已修复」之后）

- 删除本机 IP 当天的限流计数后，用同一场景重测：`POST /api/compare` **仍然返回 502 `OPENAI_ERROR`**，但这次 **约 17.7 秒**才失败（上午只要 1.5–2.6 秒）。
- 同一时段的生产日志里，复测前后几分钟的其他 compare 请求也都是 `decision_fail`（另有 1 次 400、几次 429）。最近一次生产部署在复测前约 6 分钟，没有新的代码提交；`OPENAI_API_KEY` 仍是 13 天前设置的。
- **推断（未证实）：** 失败从「秒回」变成「十几秒」，说明 OpenAI 现在可能已经能正常响应（例如额度或账单问题已解决），但后面的步骤仍然失败。候选原因优先怀疑输出被 `max_tokens: 1800` 截断导致 `JSON.parse` 失败，或 OpenAI 业务错误；`normalizeCompareResult` 一般不抛错。要确认，看部署后的 `[compare] model_fail` 日志。
- **所以这次仍然没拿到我方的推荐结果，第 2 节我方一栏继续沿用 2026-09-28 的旧实测。**

### P1：失败请求也计入每日额度，到上限后仍显示「Try again」（已修）

- **复测时的行为：** `lib/rate-limit.ts` 在调用 OpenAI **之前**就计数，被拒的 429 请求也会继续增加计数（本机 IP 当天计数到了 8）。真实用户遇到 502 时点 3 次「Try again」，之后即使服务恢复，当天也用不了了。到达上限后，页面同时显示限额文案和一个无用的「Try again」按钮。
- **已改（同日后续提交）：** 只在成功响应后 `consumeDailyLimit`；失败不烧额度。到上限时隐藏「Try again」。

### P1：失败时用户只能看到一句「Try again」

这时用户没有任何可用的东西：没有降级结果，也没有「稍后再来」的说明。Layla 同一时刻给出了完整行程。（之前决定不用示例数据冒充真实结果，这个决定是对的，但需要一个诚实的降级方案。）

### P1（遗留）：普通比较模式里「避开长途飞行」仍不是硬约束

2026-09 已发现，至今没修。普通比较模式只把 Avoid 写进提示词；航程硬校验只在 Surprise me 的 `lib/inspire-validate.ts`。这次 Layla 恰好就栽在这一点上，所以它从「待改进」变成了能直接拉开差距的地方。

## 4. 对产品的启示（事实 / 推断 / 建议分开）

1. **事实：** Layla 免注册，并且已经能给出「首选 + 备选 + 淘汰理由」。
   **推断：** 「先比目的地」和「免注册」已经不能单独当卖点。
   **建议（需要你决定）：** 把对外卖点从「先比目的地」改成「**说到做到的约束**」：说避开长途飞行，就绝不推荐 27 小时的航程；说预算 $2,000，就绝不悄悄给出 $2,500 的方案。
2. **事实：** Layla 违反约束后会自己写出警告，但把它折叠了，首选也没变。
   **建议：** 在普通比较模式里也加上服务端的硬约束校验（复用 Surprise me 模式的航程校验）。被约束排除的候选，在「为什么不选」里明确写出「因为你说要避开长途飞行」。这是一个能现场演示的差异。
3. **事实：** Layla 有站内结账和免费真人专家，背后是 Expedia。
   **建议：** 仍然不拼预订，保持联盟链接和诚实披露（与 2026-09 的结论一致）。
4. **事实：** Mindtrip 主打长期偏好记忆。
   **建议：** 偏好记忆仍然需要账号，继续搁置。可以先做一个不需要账号的版本：本机记住上次的出发地、预算和避开项，作为可选功能。
5. **最优先：** 先恢复线上服务，再谈其他。修复建议：
   - 在 catch 里记录 OpenAI 的状态码和错误类型（不记录 prompt 和 key）；
   - 检查 OpenAI 后台的额度、账单和 key 状态；
   - 加一个定时的线上健康检查（每天真实请求一次 `/api/compare`），失败时告警。
