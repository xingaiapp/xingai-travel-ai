# ADR 0006：旅行故事放在决策之后，永不参与评分

**状态：** Accepted  
**日期：** 2026-09-26  
**作者：** Xing @ XingAI  
**取代：** —  
**被取代：** —  
**语言：** [English](0006-stories-after-decision.md) · 中文

## 背景

旅行故事（`/stories`）发布亲身经历的旅行（先香港，后 Los Cabos），带有诚实的判断：会再去、会跳过、私藏好地方、教训。它让产品有“人”的感觉，并把搜索流量带进 `/decide`。

顺手的下一步是把这些体验喂进决策本身（“胜出：香港——Xing 在那里住了半年”）。这会产生 ADR 0004 为联盟链接解决过的同一种冲突：

- **覆盖偏差**——只有发布者去过的目的地才有“真实证据”，会系统性地显得比没有故事的地方更强。
- **单一样本**——在一座城市住半年，不能说明一家人去那里玩一周是否合适。
- **创作者偏好**——发布者的偏好和佣金一样，是一种激励。

## 决策

**故事是决策之后的可选阅读。永不影响胜出者、排名、置信度或权衡说明。**

1. **`/result`**——`components/related-stories.tsx` 渲染在对比、权衡、优先预订和行程之后。它列出**所有**参与对比的目的地（无论是否胜出）的故事，按对比顺序，并标注为“一个人的经历，没有影响上面的结果”。
2. **匹配**——`lib/stories/index.ts` 中的 `storiesForDestinations()` 仅按目的地名称匹配。故事数据不传给 `/api/compare`、`/api/inspire` 或 `/api/plan`，prompt 中不得提及故事。
3. **故事 → 决策**——故事页 CTA 链接到 `/decide?places=…&region=…`，只把目的地预填为一个选项；约束条件由读者自己填写。
4. **判断由人写**——`take`、`quote` 和“会不会再去”的文字由发布者本人撰写。AI 可以排序照片、起草 alt 文本、提示缺失字段，但不得编造第一人称判断。
5. **度量**——`POST /api/track` 记录 `story_from_result` 和 `story_to_decide`（`[story-click]`）。发布两集后设检查点：继续、调整或停止。

明确禁止：

- 在对比表或胜出标题中出现故事数量、“真实体验”徽章或发布者引言。
- 因为是否有故事而调整目的地排序或置信度。
- UGC（评论、点赞、“分享我的体验”）——在有登录、审核和更新后的条款/隐私政策之前不做，另立 ADR。

## 后果

**正面**

- 决策可信度不受影响；故事增加深度而不增加偏差。
- 故事有可度量的任务：把读者带进 `/decide`，并给做决定的人提供真实的内容。

**负面**

- “真实人类证据”的差异化弱于把它作为评分信号。
- 只有有故事的目的地才显示该区块；这种不均衡可见，但位于决策之下。

## 曾考虑的替代方案

- **故事作为评分输入**——拒绝；覆盖偏差与创作者偏好。
- **只为胜出者显示故事**——拒绝；用发布者的权威强化胜出者。
- **现在开放 UGC**——推迟；需要登录、审核、法律页面，以及故事有人读的证据。
